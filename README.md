# geo-audit

**给一个域名，输出一份 HTML 报告：AI 抓你的站时，哪些位置读到的是错的。**

不是 SEO 打分，不是「AI 友好度 87 分」。

两个实测数字说明它跟同类工具的差别在哪。

## 一、去噪：假阳性 40.5% → 3.85%，漏报 0

同一批 42 个候选链接，`scripts/fp_gate.py` 每次 CI 都重算：

|  | 判死 | 假阳性 | 漏报 |
|---|---|---|---|
| 只看首跳状态码（≥400 即判死） | 42 条 | **17 条（40.5%）** | — |
| 本工具 | 26 条 | **1 条（3.85%）** | **0 条** |

差在这五类，每一类都是实测踩出来的：URL 模板占位符（`{permalink}` / `${...}`）、
地理限制的 404、机器人挑战被误读成 429/403、UA 反爬、只跟第一跳跳转。

那 1 条假阳性（H41）是站方后来把现象修掉造成的漂移，按 §8.1 的规程不改断言、
只留痕，所以门禁口径下是 0 —— **但当前实测就是 1 条，这里不写 0。**

## 二、它会否定自己的输出

[gusto.com 那份报告](docs/reports/gusto.com.html)第一行是：

> **这次扫描不可信：18 个核心位置里有 17 个我们没能评估。下面的结论不要当结论用。**

Cloudflare 挡掉了几乎所有位置 —— 而它的 `llms.txt` 其实是真文件。核心位置里超过
一半无法判断时，报告就这么写，CLI 退出码是 2。

**把「我们没看到」写成「你没问题」是这类工具最常见的骗法。**
`Status.UNKNOWN` 在这份代码里永不折算成通过，四格计数之和恒等于位置数，有闸门守着。

## 它输出的是这种句子

（下面这段是 [mistral.ai 的报告](docs/reports/mistral.ai.html)里的原话，
不是示意文案）：

> **HIGH · AI 通道内部 · ④ 索引内链存活**
> `llms.txt` 里列的 `https://docs.mistral.ai/docs/deployment/cloud/sfcortex.md` 是死链。
> 该索引 **75 条死 / 0 条活**。
> 只探根路径、不做对照探测的实现会说：未采纳（没探这个位置）。
> 实际是：索引里列的这条链接死了（75/75 条判死）。
> 复现：`curl -sSL -A 'geo-audit/0.1.0 (…)' 'https://docs.mistral.ai/docs/deployment/cloud/sfcortex.md'`
>
> 改 1 处 → 修 75 条：补页面或改指到现存页。

- **openstatus.dev** —— 10 个位置 robots 禁止、6 个撞预算，另外 **8 个位置

## 跑一次

    uvx geo-audit yourdomain.com --contact you@yourco.com

Python 3.11+。`pipx run geo-audit …` 和 `pip install geo-audit` 一样。
报告是单个 HTML 文件，零外部请求、零 JS，可离线转发、可直接打印、可贴进工单。

真实运行长这样（`--replay-fixtures` 是用仓库内冻结快照跑，零网络）：

```
$ geo-audit mistral.ai --contact you@yourco.com

geo-audit 0.1.0 · mistral.ai
UA: geo-audit/0.1.0 (contact: you@yourco.com) · 0.5 req/s
robots.txt  遵守（被 Disallow 的位置标「无法评估 · robots 禁止」）
[1/6] ① 入口发现      探 5 个位置 … 3 处有文件
[2/6] ② 索引文件真伪    2 个位置
[3/6] ③ 全文通道      3 个位置
[4/6] ④ 索引内链存活    FAIL 75 死 / 25 活
[5/6] ⑤ .md 通道      有声明但判据不足，按设计不报
[6/6] ⑥ 可点击路径     抽取 0
完成 · 18 个位置：1 读错 / 5 无法判断 / 9 通过 / 3 不适用 · 用时 287s
```

**不会用命令行？** Fork 本仓库 / 点 "Use this template" → Actions →
`audit-my-domain` → Run workflow → 填域名和邮箱 → 两分钟后在同一页面下载 HTML。
不用装任何东西。（那个 workflow **刻意不自动发到 Pages**：把别人家域名的体检结果
推成公开页面，是我们没有权利做的事。artifact 保留 30 天，谁跑谁看。）

## 它只查两类东西，都是零 LLM 的机械判定

报告里 `llm_calls` 恒等于 0，且有 CI 门禁 grep 着判定层不许出现任何 LLM 调用。
判定函数不接 LLM client —— 同一输入必得同一输出。

**① AI 路径体检** —— 你的 `llms.txt` / `llms-full.txt` / `.md` 通道是真的能用，
还是只是看起来存在。每一条判定都跟一个**对照探测**：我们同时请求一个随机编造的
路径（`/geo-audit-probe-<随机十六进制>.txt`），两边一比才下结论。
拿回来的东西和编造路径拿回来的是同一份骨架 → 那不是你的索引，是你的页面外壳。

**两把尺子**：文本位置还会用 `Accept: */*` 再量一次。原因是我们量出来的 ——
100 个真实 AI 路径位置里，**9 个的答案取决于请求头**：

    openstatus.dev / dev.wix.com 的 llms.txt
      带 text/markdown -> 404 几百字节      */* -> 200 真文件
    ecwid / attio / pipedrive / printify / moderntreasury 的 llms.txt
      带 text/markdown -> markdown 正文     */* -> HTML 页面壳

第二类更要命：只用一把尺子的话，工具拿到 markdown 就判「通过」，而发 `*/*` 的
抓取器拿到的是页面壳 —— **正是这个工具专门在找的那种缺陷，被请求头挡住了**。
两把尺子不一致时这个位置判「无法判断 · 答案取决于请求头」，两边读数各带
`curl` 复现命令写进报告。我们不替你决定哪一把才算数：那要先有「AI 抓取器实际
发什么 Accept」的分布数据，而我们没量过。

**② 死链** —— 只报「人和 AI 都会点、点了就 404」的链接，按**根因**归并、按**位置**
分级。销售路径上的一条和页脚社交图标上的一条，我们不当成同一件事。

## 它明确不查

锚点腐烂、sitemap、robots 对 AI 爬虫的放行、图片/CSS 资源、**事实是否自相冲突**、
**内容是否过期**。

最后两项不是没想到，是试过之后砍掉的，理由是我们自己的实测数字：

- **内容过期**：通用「旧年份」正则在两批独立样本上扫出 **134 条命中 0 条真信号、
  296 条命中 2 条真信号**；人工复核那 21 条过期信号时，**推翻 1 条、降级 3 条、
  重复计 3 条**。做进产品就是骚扰。
- **事实冲突**：自动化版本**从来没跑过**，所以这一整块的假阳性率是空的 —— 我们不
  知道它会错到什么程度，那就不能发。（而且「属性对」这个计数单位实测伸缩 15 倍：
  同一张套餐表，一个域记成 1 对，另一个记成 17 对。）

把没验证过的检查装进产品，是这类工具第二常见的骗法。

## 为什么报告第一页不是问题清单

因为大多数域名报不出多少条。我们在 72 个域名上实测过：
**20.8% 一条都报不出来，52.8% 只有 1–2 条，只有 26.4% 能报 3 条以上。**

一份只有 2 条的报告卖不出去，但那 2 条所在的**位置**和**根因**是真值钱的：
11,608 条链接查出 94 条死链，**其中 66 条挤在 7 个域名上**；
mistral.ai 那份里 76 条 finding 收敛成 **1 处根因**——「改 1 处 → 修 75 条」。

所以第一页是你的 AI 检索链路图、六段里每一段的通过/失败/无法判断，以及一张
对照表：**只探根路径、不做对照探测的实现，会在你的哪几个位置上读错。**
（这句话说的是一种实现方式在你这几个具体位置上的行为，每条都附 `curl` 命令
自己复现。我们没有拿任何别的产品跑过对照，所以不会替它们说话。）

## 「无法判断」是独立的一态

会落到这一态的：WAF 挡了、限流了、正文是 JS 渲染的、robots 不让抓、撞上请求
预算上限。报告里那一整区（「未能评估」）**排在发现之前**，每条都写清原因码和
怎么重跑 —— 排在后面就等于默认没人看。

（为什么这件事是重点，见开头第二节。）

## 抓取行为

- 单域名每 2 秒 1 个请求（`--rate` **只能调慢**，调快直接报错退出）；
- User-Agent 里必须带你的联系邮箱（`--contact` 缺失直接退出 4，
  `--replay-fixtures` 和 `--from` 也不豁免）；
- 默认遵守 `robots.txt`；被 Disallow 的位置标「无法判断 · robots 禁止」，
  不会标成「通过」；
- 只抓无需登录的公开页；**不绕 WAF、不解 CAPTCHA、不用住宅代理**。
  遇到挑战页就标「无法判断」然后走开；
- 单域请求硬上限默认 120（`--max-requests`），超限的位置标「无法判断 · 超出预算」，
  而不是悄悄跳过。

**没有托管 web 版，这不是偏好问题。** 托管版意味着我们代替你去抓第三方域名，
UA 里的联系邮箱就变成我们的而不是发起人的（`--contact` 这条约束当场失效），
而且一个「输入任意域名就发请求」的公开端点就是开放抓取代理，会被用来打人。
CLI 和 GitHub Action 的形态里，请求永远从你自己的出口发出、UA 里是你自己的邮箱。
